COMPLETED

Make the GitHub project usable and strengthen model credibility

2026-07-25 · GreenLight Simulation

User request

Research what a usable public GitHub project and a greenhouse-industry side project need, improve the current model, keep all work inside the authorized Greenlight-simulation repository, and record every update in an English HTML log.

Research translated into a product decision

GitHub's community-profile guidance identifies a README, contribution guidance, security policy, issue and pull-request templates, and a clear license as core public-project signals. FAIR4RS emphasizes that research software evolves and therefore needs explicit versioning, executability, and reuse metadata. WUR greenhouse digital-twin research shows that useful decision support combines sensor-aware calibration, scenario generation, resource efficiency, and held-out evaluation. The EPA model-evaluation framework separates software behavior from operational, diagnostic, dynamic, and uncertainty evidence.

The resulting decision was to invest this iteration in model provenance, diagnostic contracts, automated CI, and contribution structure instead of adding another unvalidated dashboard feature. The project remains an explainable pre-deployment workbench, not a production controller or agronomic adviser.

Model and comparison improvements

  • Fixed a reproducible comparison defect: changing weather in browser mode previously retained the old horizon and accumulated resources while assigning a new run ID. All engine modes now stop and reset when the scenario changes.
  • Added browser model version 2026.07 and versioned economic assumption ID browser-fixed-eur-2026-07.
  • Added equivalent full-model provenance using the GreenLight-Gym2 package label, adapter version, parameter fingerprint, selected-weather fingerprint, and exact Git revision when available. A sandboxed integration run demonstrated the safe fallback: when Git metadata could not be resolved there, the adapter used a SHA-256 fingerprint of only the exact gl_gym Python modules loaded into the process. The final local server resolved the source Git revision normally.
  • Upgraded saved baseline schema to version 2 and blocked deltas when model or cost-assumption versions differ.
  • Added finite-value and range validation for scenarios, modes, controls, targets, and step counts. Invalid UI target values revert to the last valid model value.
  • Moved browser heat, lamp, and CO2 prices into an explicit immutable assumption set and returned it in every snapshot.

Model credibility and GitHub usability

  • Added MODEL_CARD.md with intended uses, unsupported uses, engine boundaries, economic assumptions, current evidence, known limitations, reproduction steps, and a staged validation roadmap.
  • Added deterministic Node tests covering all four scenarios, finite/bounded values, monotonic cumulative resources, reset behavior, bad-input rejection, and directional heating, ventilation, CO2, and lamp responses.
  • Added least-privilege public GitHub Actions CI for the default Python contracts and browser-model tests. All actions are pinned to exact commits, checkout credentials are not persisted, and package-manager caching is disabled.
  • Added CONTRIBUTING.md, SECURITY.md, a pull-request checklist, and structured bug, feature, and model-validation issue forms.
  • Updated the README and product strategy to expose the model card, contribution path, CI, evidence limits, license status, and next priorities.
  • Kept the missing software license explicit instead of choosing legal terms for the owner.

Cost and safety controls

  • No OpenAI API, API key, usage-billed AI service, Fast mode, credit purchase, or paid add-on was used.
  • The GitHub Actions workflow uses the repository's public standard runner, read-only token permission, no cache upload, and no artifact upload.
  • No parent directory was listed and no protected repository, thesis file, dataset, experiment output, or research result was modified.
  • The full-model integration imported only the exact read-only GreenLight-Gym2 source with PYTHONDONTWRITEBYTECODE=1 and Python -B.
  • All environment and runtime files remained inside Greenlight-simulation.

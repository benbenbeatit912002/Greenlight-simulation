User request

The user asked what is still missing from the simulator. This turn reports implementation gaps rather than changing application behavior.

Verified current state

The local status endpoint reports browser mode and scientific=false. The upload endpoint explicitly returns simulationReady=false and stored=false. Existing controls include start/pause, reset and speed selection. The full-model adapter still selects fixed scenarios, points weather loading at its external source checkout and retains only 97 history entries. Recommended implementation order

  1. Connect validated simulator-owned weather to the unchanged full GreenLight-Gym2 source with verified units, missing-input policy, initialization and coverage checks. Preserve the read-only research boundary.
  2. Add run start/end dates, visible full timestamps, single-step operation and saved-state playback. Playback speed must not change physical integration semantics.
  3. Document a reference greenhouse and crop initialization, then expose supported geometry, cover and equipment parameters instead of suggesting that weather alone defines a user's greenhouse.
  4. Persist complete runs inside the simulator and export climate, controls, resources and provenance. Extend the existing comparison feature to identical uploaded-weather conditions rather than rebuilding it.
  5. Audit model-derived versus illustrative fields, then evaluate against explicitly authorized or openly licensed independent observations before claiming predictive accuracy.
  6. Verify reproducible installation without the owner's research checkout, document model/version and licensing requirements, and publish the reviewed feature when requested.

The immediate priority is the complete path from uploaded weather through the real model to displayed results. Additional visual polish is secondary to this functional gap.

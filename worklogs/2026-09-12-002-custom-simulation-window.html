M2: Custom simulation dates and exact stopping

12 September 2026

Request and outcome

Continue milestone M2: show uploaded weather coverage, select start/end times, show duration and step count, validate initialization and look-ahead coverage, and implement progress, pause and exact endpoint stopping without fabricated weather. This milestone is now implemented for Amsterdam-format uploaded weather and verified against the full GreenLight-Gym2 model.

Decisions and assumptions

  • The user supplies the actual source year (1900–2100) and either UTC or fixed source-local standard time. The application does not infer timezone, apply daylight-saving changes or use the viewer's computer timezone.
  • Windows are half-open [start, end), with both boundaries aligned to the fixed 900-second model step. A 09:15–10:00 run contains exactly three steps. Playback speed changes pacing and batch size only.
  • Initialization uses GreenLight default states at the selected source timestamp. Warm-up is explicitly zero hours; startup transients are included. This is not equilibrium initialization or greenhouse calibration.
  • The controller needs complete daily radiation context. Uploaded weather must include midnight-to-midnight data for every simulated day and at least 12 hours after the selected end. The selectable range reflects both requirements. A partially covered first day is excluded.
  • The existing 36-hour upload minimum, 300-second source grid, 2 MiB limit and 10,000-record limit are retained. No missing samples are filled and no next-year data file is opened.
  • Source-year seconds drive the model clock, its time state, daily radiation and upstream seasonal soil-temperature estimate. The Netherlands soil estimate remains a disclosed assumption, not a country-specific calibration.
  • Pause prevents new requests but permits an already requested batch to finish. A completed run cannot advance further; resetting explicitly starts another run.

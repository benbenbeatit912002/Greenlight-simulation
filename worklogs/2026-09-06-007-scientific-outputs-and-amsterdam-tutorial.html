Configuration locations

  • GreenLight-Gym2/gl_gym/configs/default_params.py: greenhouse dimensions, cover properties and equipment. Floor area is 144 m2, main air height 5.7 m, mean greenhouse height 6.2 m, boiler power 130 W/m2 and lamp electricity 116 W/m2.

  • GreenLight-Gym2/gl_gym/environments/utils.py::init_state: initial greenhouse and crop state.

These are upstream model defaults, not a calibration for an arbitrary visitor's greenhouse.

Implementation and decisions

  • The public page no longer loads or constructs the legacy browser approximation. Offline or failed models hide simulation values and disable running. CLI default is glgym; historical --engine browser now serves only UI/tutorial/upload preview.
  • The adapter evaluates the exact upstream aux_states.update equations: above-canopy global radiation from sunlight and top lamps is a[42]+a[43] in W/m2 (excluding interlighting); canopy-absorbed PAR is a[191] in umol/m2/s; LAI is a[31]. Heat, lamp electricity and CO2 totals integrate a[220], a[37] and a[222].
  • Outputs use the forcing row of the just-completed step, matching upstream observation timing. Rounded values are display choices. Cutaway animation, sun/plant geometry and warning thresholds are explanatory UI, not additional spatial model predictions. Unavailable cloud data is null rather than a fabricated measurement.
  • The adapter prevents implicit next-year weather reads. Only Amsterdam 2010 is enabled. The late-autumn start changed from day 305 to 295 to fit the 60-day season plus prediction horizon within that file; other scenario starts remain unchanged.
  • Solver failure invalidates the partial run and revision until an explicit recovery reset. A backend run ID survives healthy reconnects and changes only on successful reset.
  • The bilingual tutorial specifies the original nine headers, ordered exactly: time, global radiation, wind speed, air temperature, sky temperature, ??, CO2 concentration, day number, RH. Times are numeric year-relative seconds at 300-second intervals, without inventing a timezone.
  • The tutorial discloses that the upstream loader ignores ??, CO2 concentration and day number, assumes outdoor CO2 at 400 ppm and estimates soil temperature with soilTempNl(time). The undocumented ?? field is not described as soil temperature.
  • The spreadsheet skill guided preservation of the existing two-sheet template, typed numeric inputs, explicit units and visual verification. The new template has 289 synthetic five-minute records over 24 hours. It contains no copied research observations. Existing v1 uploads retain backward-compatible validation.

Important remaining limitation

Excel uploads still validate and preview only. They do not replace the running GreenLight weather. The interface, workbook and README all say this explicitly. Custom-weather model execution, configurable greenhouse parameters and predictive validation remain separate work. Using the original model does not prove accuracy for another greenhouse.

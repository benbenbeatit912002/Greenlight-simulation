Test applied greenhouse state and blank-field defaults

3 October 2026

Request and conclusion

The user requested testing after Apply to check whether the greenhouse state is reasonable and asked whether empty inputs use defaults. Verified that Apply uses the requested parameters/states and empty greenhouse fields inherit model defaults, not zero. Numerical and software checks passed. However, day-long simulations crossed existing climate warning thresholds: these results do not establish suitable growing conditions, calibrated predictions or robust automatic control.

Default behavior verified in the browser and model

  • All 22 fields blank produces an empty override dictionary and reproduces the default parameter/state identity for the same weather and seed.
  • After applying custom settings, clearing only initial air temperature restores the default temperature while preserving still-filled RH, CO₂ and geometry overrides.
  • Clearing other fields and retaining only RH restores the full default parameter vector and every initial state except vapor pressure, verified against the live model arrays.
  • The ordinary top Reset command omits a new configuration and preserves applied overrides. This differs from clearing form inputs and explicitly applying the resulting sparse configuration.
  • Use model defaults changes the draft only; Apply initializes the default run. Successful initialization resets step/resource counters and history. Reload retains applied settings.
  • Length/width remain optional calculator inputs. Blank calculator values do not set the model floor area to zero.
  • Defaults can conflict with an override: 300 m² floor area with the inherited 216.6 m² cover is rejected. Browser Apply is disabled, a forced API reset returns 400, and the healthy prior run is preserved.
  • Current built-in default examples: 144 m² floor, approximately 216.6 m² cover, 5.7 m main height, 6.2 m mean height, 16.5°C initial main air and 90% initial RH. The initial RH already exceeds the dashboard's 85% warning threshold. Defaults are inherited model assumptions, not guarantees of ideal conditions.

Controller behavior, equipment assumptions and initialization warrant a separate diagnostic/tuning task; numerical correctness is not agronomic validation.

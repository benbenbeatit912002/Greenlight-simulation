Weather adaptation versus automatic greenhouse calibration

3 October 2026

User request

The user asked whether uploading weather from different locations could automatically calibrate the simulator. This request was treated as a feasibility and product-design question, not authorization to implement fitting or access additional research data.

Findings and recommendations

  • Weather ingestion and model calibration are different operations. Outdoor weather supplies model forcing; by itself it does not identify the greenhouse parameters or demonstrate agreement with real indoor conditions.
  • The existing project already converts its specified Amsterdam-format Excel schema and drives the full model. Arbitrary weather-file formats, automatic unit/timezone inference and measured-data fitting are not implemented.
  • A future import assistant could suggest column mappings, convert explicitly confirmed units and clocks, and report missing coverage. Ambiguous fields and assumptions need user confirmation; missing measurements must not silently become fabricated data.
  • Site calibration needs synchronized weather, observed indoor variables, known geometry/equipment and historical actuator inputs. Crop fitting additionally requires relevant crop measurements. The current automatic controller must not substitute for unknown past actions.
  • A bounded first calibration release should focus on temperature and humidity, with a small identifiable parameter subset selected after sensitivity checks. Keep measured geometry fixed and impose physical bounds and evaluation limits. Use a local numerical optimizer without a billed AI service.
  • Separate fitting and held-out periods before optimization. Compare default and fitted predictions, report errors such as MAE/RMSE, and state failures and uncertainty. Improvement on unseen data is not guaranteed.
  • Calibration is specific to a greenhouse and observation period, not universally to a country. Weather compatibility is useful even when calibration data are unavailable.
  • The current uploaded-weather path still uses the upstream Netherlands soil-temperature estimate. A broader-location release should expose a justified local soil-temperature input or explicitly chosen estimation assumption instead of implying that a weather upload removes all regional assumptions.

Evidence

Read AGENTS.md and inspected the project's weather-input guide, scientific-validation guide, model card, M5 implementation plan and backend/weather_conversion.py. The plan already distinguishes weather adaptation from future greenhouse-specific calibration.

Consulted the official GreenLight-Gym2 parameter documentation and weather documentation. These document separate model parameters and outdoor-weather inputs. The proposed calibration workflow is a recommendation consistent with the local plan, not a claim that upstream or this dashboard currently supplies automatic site calibration.

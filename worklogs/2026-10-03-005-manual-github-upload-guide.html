Explain manual upload to the existing GitHub repository

3 October 2026

User request

The user asked how they can manually upload local Greenlight-simulation changes to GitHub. They requested instructions, not an upload action.

Findings and guidance

  • The existing local checkout points to https://github.com/benbenbeatit912002/Greenlight-simulation.git and was previously confirmed on main. The ongoing feature and worklog changes are local until they are committed and pushed.
  • Recommended the visual GitHub Desktop workflow: add the exact existing local repository, confirm the existing origin and main branch, review the Changes list for project files, enter a commit summary, commit locally, then select Push origin. Do not choose Publish Repository because the remote already exists.
  • Before pushing, verify that .venv, .runtime, caches and all protected practice/research files are absent from the Changes list. Never force-push. If a fetch, branch mismatch or conflict prompt appears, pause and review its exact message.
  • Browser-only upload is appropriate for a small number of individual files, but the GitHub website is less suitable than Desktop for an existing multi-file project because a commit and push preserve the repository's normal version history and directory structure.

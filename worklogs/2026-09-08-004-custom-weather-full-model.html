Uploaded weather drives the full GreenLight model

8 September 2026 — M1 implementation and verification

Request

Advance the public Greenlight-simulation project toward a usable country-adaptive greenhouse tool: accept a weather workbook, convert it using GreenLight-Gym2-compatible equations, run the scientific model, visualize the resulting greenhouse state, and record the work in English HTML logs. The work stayed inside the authorized simulator repository. The protected GreenLight-Gym2 source checkout was imported read-only only for model execution and compatibility checks.

Completed

  • Added an in-memory Amsterdam nine-column weather conversion path. It resamples the validated 5-minute workbook to the 15-minute GreenLight disturbance grid and maps radiation, air temperature, humidity, CO2, wind and sky temperature using upstream conversion functions.
  • Added the required 36-hour coverage check: 24 hours of model window plus the 0.5-day controller prediction horizon. The selected upload window is normalized to simulation day 1 so the model clock, day/night controller and daily-light calculations agree.
  • Added explicit staging and activation. Uploading validates and stages weather without resetting the current run. The user must select Run with this weather.
  • Separated conversionReady from modelReady. The first means the weather conversion is staged; the second is true only after a successful GreenLight reset.
  • Made environment replacement transactional. If a candidate custom-weather reset fails, the previous healthy environment and its run state are retained.
  • Retained at most two in-memory datasets: the active dataset and one pending dataset. Datasets are not persisted and remain only until replacement or server shutdown.
  • Updated the public Excel template to 433 synthetic 5-minute records covering 36 hours. The exact nine Amsterdam headers and the Instructions sheet remain intact. No protected weather data was published.
  • Updated the bilingual upload tutorial, readiness messages, model-status labels, README, model card, implementation plan, and API documentation.

Reviewer follow-up

A read-only reviewer inspected the implementation after the first pass. The reviewer identified readiness-state ambiguity, environment replacement risk, reconnect label ordering, stale retention wording, and a missing real HTTP integration check. The justified recommendations were applied: readiness fields were split, reset replacement now rolls back safely, reconnect reads the active weather identity before updating labels, documentation now states the two-dataset memory bound, and a real-model HTTP upload test was added.

Scope still remaining

The current upload contract is intentionally the Amsterdam nine-column format. It does not yet provide arbitrary country schema mapping, selectable simulation start/end dates, editable greenhouse geometry/equipment/crop initial states, result export, or greenhouse-specific parameter calibration. Weather adaptation is not the same as greenhouse calibration; those are separate planned milestones in IMPLEMENTATION_PLAN.md.

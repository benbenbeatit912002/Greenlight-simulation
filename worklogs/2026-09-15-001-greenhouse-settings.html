M3: Run-local greenhouse settings and initial states

15 September 2026

Request and outcome

The user asked to continue after M2 custom simulation dates. Implemented the first bounded M3 release: 22 audited greenhouse, equipment, cover and initial-state inputs connected to the full GreenLight-Gym2 model. A bilingual panel separates draft edits from explicit initialization and distinguishes per-area resources from whole-greenhouse totals.

Decisions and assumptions

  • Operate only in the explicitly authorized Greenlight-simulation path. Preserve all previous dirty files and do not mutate either practice repository.
  • Read exact upstream source interfaces for parameters, initialization, observations, rewards and auxiliary equations. The supported subset is documented in GREENHOUSE_CONFIGURATION.md; it does not pretend to expose every GreenLight parameter.
  • Geometry: floor area, cover area, main/mean height and roof vent geometry. Area fields remain independent. Height-dependent air/CO₂ capacities are recomputed using upstream equations.
  • Boiler and CO₂ inputs use capacity per floor area; model totals are recomputed from actual floor area. Lamp input remains electrical W/m². Zero capacity disables output but does not remove thermal hardware or leakage.
  • Cover inputs expose PAR/NIR transmission, thickness and conductivity. Other optical/thermal properties and screens remain defaults. No complete glass/polycarbonate preset is claimed.
  • Initial-state inputs expose main-air temperature/RH/CO₂, leaf/stem/fruit dry mass, canopy temperature, 24-hour canopy state and crop temperature sum. Top air, surfaces, soil, carbohydrate buffer and other unexposed states remain defaults. Main-air temperature-only changes retain default RH and ppm through upstream conversions. LAI is derived from leaf mass.
  • Defaults describe an established tomato crop. There is no seedling preset, warm-up, parameter fitting or claim of measured-data accuracy. Bounds are supported software limits, not agronomic guidance.
  • Every reset builds a candidate environment before replacing the healthy run. Effective parameter vectors are supplied through a run-local provider. Observations, x_prev and cached reward normalization are refreshed. Upstream source/default arrays remain untouched.
  • Actual effective parameter and initial-state arrays are fingerprinted. Configuration identity also includes selected-window metadata. Numeric comparisons are blocked across differing settings/initial states and for old baselines lacking evidence.

Read-only review and disposition

One initial review and one follow-up were performed. The reviewer did not edit files, run tests, create caches or access protected sibling paths.

  1. Same-run reconnect left settings disabled. Accepted. Availability recovery refreshes the form/buttons/status while preserving the draft. Browser regression forces a failed step, reconnects to the same run and verifies settings become usable.
  2. Configuration-only reset lost uploaded weather identity. Accepted. The server retains the active window and resolves omitted selection to the active upload. The adapter inherits weather ID/label. A real-model application test activates A, changes configuration only, stages B and successfully reselects A with unchanged weather identity/fingerprint.
  3. Rebuilding the panel cleared incomplete numeric drafts. Accepted. Existing native number inputs are reused without resetting their value on language/new-run rebuilds. The browser verifies that an incomplete 1e remains invalid and Apply stays disabled across both changes until corrected.

The single follow-up found no new actionable issues in the fixes.

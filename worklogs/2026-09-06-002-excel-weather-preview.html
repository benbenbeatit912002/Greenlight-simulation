Excel weather upload and preview

2026-09-06 · First implementation milestone completed

A bilingual upload panel, downloadable synthetic workbook, bounded validation and input preview are available. Uploaded weather is not yet connected to the scientific simulation.

User request, decisions and safety

The user asked to begin the weather-driven greenhouse project described in the preceding design assessment, then asked to continue after a quota-related tool interruption. The first milestone implements the input contract and preview before connecting arbitrary weather to GreenLight-Gym2. No model equations, actuator logic, or existing simulation behavior were changed.

All project commands used the explicitly authorized Greenlight-simulation working directory. Neither practice repository was searched, read, imported, tested or modified. No research observations, manuscripts, experiment outputs or other protected material were accessed. The previous design log and its index entry were preserved.

Free open-source dependencies were installed only into this project's virtual environment, with its own uv cache and temporary directory. Bundled authoring/browser libraries were used read-only. Build intermediates, browser profiles, screenshots and server logs were directed into the simulator. No additional credits, paid API, Fast mode or paid add-on was enabled or purchased, and no quota-reset credit was redeemed. Work resumed only after the included quota was available again.

Delivered behavior

  • The Import your outdoor weather panel supports English and Traditional Chinese, local XLSX upload, progress feedback, error messages, coverage and range summaries, and a horizontally scrollable preview of the first five records.
  • The Excel template contains an English Instructions sheet and a Weather sheet with 97 synthetic, 15-minute records covering 24 hours. The example is explicitly labelled as invented, not measured or calibrated data. Extra model-input columns are left blank without inference.
  • Schema weather-xlsx-v1 requires UTC timestamps, outdoor temperature, outdoor RH, global solar radiation and wind speed. Sky temperature, soil temperature and outdoor CO2 are optional for preview, but must each be entirely populated or entirely blank.
  • Timestamp, unit, numeric-range, missing-value, duplicate-time, ordering and regular-interval checks run before a preview is returned. Native Excel date cells are interpreted as UTC; timestamp text requires an explicit offset. No silent interpolation, filling or weather assumptions are applied.
  • The endpoint returns input ranges, coverage, missing additional columns, SHA-256 fingerprint and at most 30 structured issues. It never saves uploaded bytes, changes simulation state or increments the model revision.
  • The UI and response explicitly report preview-only status. Even complete columns return simulationReady: false and stored: false.

Security boundaries

  • Uploads are bounded to 2 MiB compressed, 16 MiB uncompressed, 256 package entries, 10,000 records and eight columns. Complete strings and diagnostics are bounded.
  • Formulas, macros, external links, embedded objects, unsafe package paths, non-XML attachments, duplicate cell coordinates and ambiguous worksheet row coordinates are rejected. XML parsing is hardened, and worksheet checks do not depend on conventional package locations.
  • Only one workbook is processed at a time. Local Host/Origin and a custom request header are checked, with no CORS allowance and a bounded upload-read timeout.
  • GET and HEAD serve only explicitly public assets, selected documentation, work-log HTML and the template. Directory listings, private runtime files, source files and paths resolving outside the simulator are blocked, including the root index selection.
  • This remains a local development server, not a hardened multi-user Internet service. Public deployment requires a separate authentication, isolation, resource-control and hosting review.

Review recommendations and disposition

One read-only reviewer performed one initial review and one follow-up review. The two-round limit was respected.

  1. Bound assembled rich/shared strings and avoid exception messages echoing large input values: accepted, fixed and covered by fragmented-string and bounded-error tests.
  2. Validate actual worksheet parts, row indices and row/cell consistency rather than conventional ZIP filenames: accepted, fixed and covered by moved-part and mismatched-row tests.
  3. Reject duplicate coordinates that could overwrite an invalid reading: accepted, fixed and covered by an invalid-then-valid duplicate B2 regression.
  4. Resolve and check the index file itself when serving the root route: accepted, fixed and covered for GET and HEAD by a mocked escaping-index test, without creating or reading external files.
  5. The follow-up found that nonstandard part suffixes could still bypass inspection: accepted. The parser now rejects unsupported package parts, including uppercase .XML and .data variants, with regression coverage. This final correction was tested by the primary agent; no third review was requested.

Validation and runtime

  • Python: 41 tests discovered, 40 passed, one full-model integration test intentionally skipped. Tests ran with -B, bytecode disabled and protected-source integration disabled.
  • JavaScript: all seven browser-model and upload-contract tests passed. All three JavaScript syntax checks passed.
  • The saved workbook passed the actual upload parser. Every one of its 97 saved Excel timestamps matched the expected UTC schedule. An initial authoring-runtime Date conversion defect was caught by these checks and corrected using native Excel serial dates.
  • Both workbook sheets were rendered and visually inspected. The title clipping found in the first Instructions render was corrected.
  • A hidden local browser verified successful upload, invalid-workbook feedback clearing stale previews, language switching, a 390-pixel layout without page-level horizontal overflow, and no page-script errors. Checks were rerun after the reviewed server restart.
  • git diff --check passed. Git emitted its existing LF-to-CRLF conversion warnings; these were not test failures.
  • The simulator is running at http://127.0.0.1:4173/ with --engine browser. The final status check reported available=true, scientific=false and revision=0. This deliberate mode avoids importing protected model source or reading protected weather data.
